# 已知问题与检查清单

本清单是源码阅读后需要复核的技术项，未经真实设备端到端验证。建议每项建立对应现场样本和回归测试后再修复。

## P0 — 结果正确性

- [ ] **数据单位链路**：确认采集 DLL 输出究竟是 ADC 原值、显示偏移值还是电压；`f6.py` 阈值和前端传入的 `epsilon` 必须匹配。
- [ ] **同步 XY 采集**：当前 Flask 接口只有一条 `wave`，不存在清晰八边形检测；新增双通道同步输入与同步性校验。
- [ ] **DLL ABI**：桌面使用的 `libwave.dll` 与上传的 C++ Release DLL 导出不同，重新编译替换前核对导出、位宽、参数和依赖。
- [ ] **真实缺陷解释**：将正常峰谷转折、异常突变点和原始规则命中分离，不应把全部转折点称作缺陷。

## P1 — 软件逻辑和鲁棒性

- [ ] **错误状态独立**：Python 请求/设备断开与“波形不正常”应分别显示，避免网络失败被记录成波形异常。
- [ ] **异常点坐标**：核查 Worker 端与 Pinia store 对异常点 Index 是否重复降采样映射。
- [ ] **峰峰值**：使用 `max(y) - min(y)`，而不是 `max(abs(y)) - min(abs(y))`。
- [ ] **周期切分**：零交叉噪声、偏置、周期太短、非有限值与越界需要单元测试。
- [ ] **判定形状**：加入线性度、峰谷质量；避免以少量斜率符号变化次数代替完整三角形判定。

## P2 — 维护性能与发布

- [ ] 每个请求无条件写 `document.txt` 与生成目录，需选择性保存和唯一任务 ID。
- [ ] 代码中多进程画图和每 CPU 核数预热可能占用较多资源。
- [ ] `max_pic_num` 目前限制扫描周期数量，并非成功保存的图片数量。
- [ ] 固定 10000 点截取、串行每通道 HTTP、配置持久化和采集线程负载应量化。
- [ ] 制定原始数据、现场照片、第三方 SDK 的保密/许可和 Git LFS 方案；公开 repo 不上传原始大数据。
